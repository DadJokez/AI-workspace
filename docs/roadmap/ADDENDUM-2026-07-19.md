# Comparative — Product Roadmap Addendum (2026-07-19)

Synthesized from five research passes: enterprise IT-review gap analysis, daily-driver stickiness audit, harness differentiation audit, market scan, and roadmap grounding. Everything already tracked (grounding §4) is referenced by issue number, never re-proposed.

---

## A. Thesis

**Most useful enterprise tool.** The #453 hardening arc has made Comparative's *code* trustworthy — authz tested, injection framed, audit tamper-evident, CVEs gated. What remains untracked is everything an IT reviewer and an ordinary employee check *before* reading a line of code: can I sign in with the company IdP, is the database internet-reachable, does the audit trail land in our SIEM, and does the product reach me every morning without my going looking for it. Ramp's Glass made the playbook public — zero-setup SSO, everything connected, role-recommended skills, 99% daily adoption — and no vendor sells that inside the customer's own AWS account. Comparative's positioning is "Glass, but yours": the buildable in-house workspace where usefulness compounds because identity, reach, and shared capability are org-native, not bolted on. Today the stickiness moat (skills + schedules + apps + governance) is only reachable by the engineer persona whose tools happen to be connected and who remembers to open a browser tab; the retention surface has three open issues against eight identified gaps. Closing the identity, reach, and flywheel gaps is what turns a strong harness into the default tab for all 50–500 people.

**Standing out as a harness.** The market sells autonomy — "agents run continuously," sub-agent swarms, computer use. Every one of those claims widens the trust gap that mid-size IT reviewers actually probe. Comparative's differentiation is the opposite bet: **accountability as the product**. It already owns the substrate no competitor has assembled — run-trace.v2 provider snapshots with content hashes, an LLM judge and regression gauntlet in `packages/evals`, receipts and attestations, a runs tree (#423) specced as the cost/audit spine. The three highest-differentiation capabilities in the harness audit (pre-ship verification, deterministic replay, eval-gated publishing) are recombinations of these existing assets — maximum differentiation per unit of new code. The pitch to an IT reviewer becomes falsifiable: every answer is checked against its tool evidence before it renders, every run can be replayed, every run has a budget, every published skill has a scorecard. Verification loops are the moat; scoping is table stakes everyone claims. Ship the accountable runtime and the marketing writes itself as a demo, not a slide.

## B. Proposed Epics

### Epic 1 — Identity & Org Substrate (SSO, SCIM, groups, RBAC)

**Pitch.** Nothing rolls out org-wide without production identity, and four accepted specs (#410, #411, #413, connector-governance's SCIM assumption) silently depend on an IdP group substrate that no issue tracks. Auth today is GitHub OAuth POC; the PingOne swap is claimed as "one provider config change" in TECHNICAL_OVERVIEW §4 but the cutover, session/MFA policy, SCIM lifecycle, and group resolution are all untracked build work. This epic is the enabling substrate for team memory scopes, per-group policy, per-team budgets, org-wide sharing, and deprovisioning — the single highest-leverage unblock in the tracker.

**Child issues:**

1. **SSO production cutover: PingOne OIDC replaces GitHub OAuth**
   Execute the swap TECHNICAL_OVERVIEW §4 describes: OIDC provider config, `users.ping_subject` mapping, session lifetime and MFA policy decisions, and a rollback path. Includes a migration story for existing GitHub-identified users. Exit criterion: a new employee signs in with corporate SSO and touches no GitHub account.

2. **SCIM provisioning: user lifecycle and group sync from the IdP**
   Implement SCIM create/update/deactivate so joiners get accounts and leavers lose access without manual admin work. Wire the deactivate event into #460's deprovisioning/purge hooks (which cover the data consequence but not provisioning itself). Group membership sync feeds the group substrate below.

3. **IdP group substrate: groups table + query-time membership resolution**
   Build the group model `docs/specs/memory-context-architecture.md:87` recommends (Ping group claims, query-time membership) as a first-class table, not a memory-spec side effect. This is the declared scope backbone for #413 team/org memory scopes, per-group policy, and per-team cost rollups. Design once, consume everywhere.

4. **RBAC v2: auditor and delegated-admin roles**
   `users.role` is binary `user|admin`; #458 audits admin access but nothing constrains it. Add a read-only auditor/compliance role (audit log, run traces, no user data mutation) and a delegated-admin shape so "who can see other users' runs" is answered by roles, not trust. Small schema change, large questionnaire payoff.

5. **Group-scoped connector and tool policy**
   Extend #410's tri-state policy (org-global today) to per-group overrides — e.g. Salesforce writes enabled for Sales, read-only elsewhere. Depends on the group substrate; lands as a P3 on the existing #410 enforcement work, not a new policy engine.

**Absorbs/depends:** depends on nothing; unblocks #413, #410 P2 extension, #460 deprovisioning, Epic 3's team budgets, Epic 5's org visibility. References: memory-context spec, connector-governance spec §SCIM.
**Sequence:** 1 → 2+3 (parallel) → 4 → 5.

### Epic 2 — Perimeter & Continuity (network, SIEM, DLP, residency, DR)

**Pitch.** The enterprise audit's blunt finding: the untracked tier is organizational integration, and an IT reviewer checks it before reading code. Prod RDS is publicly accessible (a docs-only open question, agentcore-migration B4/B5), the audit log terminates in Postgres plus an admin page no SOC will log into, there is no DLP answer to "employees pasting customer data into AI," residency of `us.*` inference profiles is an unconverted open question (B6), and the self-review names BCP/DR the biggest ambition-vs-state gap. Each item here is an instant questionnaire fail today and an issue-shaped fix tomorrow. This epic complements — does not duplicate — #453 Track A.

**Child issues:**

1. **Move prod RDS and services to private subnets with VPC endpoints**
   Convert agentcore-migration open items B4/B5 into tracked infra work: private subnets for RDS and ECS services, VPC endpoints for AWS APIs, security-group tightening. "Is the database internet-reachable?" must answer no. Coordinates with #467 (IaC) so the change is code, not console clicks. Human-owned change — Rob signs off on the network plan.

2. **Audit export to SIEM: streaming feed in OCSF/syslog to CloudWatch/S3**
   #456/#457/#458 make `audit_log` complete and tamper-evident; this ships it somewhere a SOC actually looks. One exporter, OCSF or syslog framing, CloudWatch Logs + S3 targets (Splunk-ingestable). Explicitly not Agent Wire (that's analytics, and blocked on schema review).

3. **DLP baseline: Bedrock Guardrails + admin-configurable PII patterns on prompts and uploads**
   Shipped redaction is storage-side only. Add pre-model inspection: Bedrock Guardrails integration plus admin-managed pattern policies (PII classes, block vs warn) applied to prompts, uploads, and connector-bound writes. First CISO question; currently no answer.

4. **Residency decision record: accept or eliminate `us.*` cross-region inference**
   Convert open question B6 into an InfoSec decision record: either pin lanes to in-region model IDs (accepting the cost delta) or document acceptance of cross-region routing with legal sign-off. Rob-owned decision; the issue's deliverable is the record plus any lane config change.

5. **BCP/DR floor: verified backups, one restore drill, RPO/RTO targets, staging environment**
   Produce evidence, not claims: automated backup verification, a timed restore drill with written results, declared RPO/RTO, and a minimal staging environment so migrations and deploys stop rehearsing in prod. Complements #449 (alarms) and #461 (runbook), which file neither backups nor staging.

6. **Legal hold override for the data-lifecycle design**
   #460's retention/right-to-delete needs a hold state that suspends deletion for named users/threads under legal or investigative hold. Right-to-delete without a hold override is itself a compliance bug. Small addition filed against the #460 design before it ships.

7. **External pen test engagement + security contact/vuln disclosure process**
   #461 produces the threat model; nothing schedules an actual test against it. File the engagement, publish a security contact, and fold findings into the readiness packet. Cheap, always asked.

**Absorbs/depends:** complements #453/#456/#457/#458/#460/#461/#449/#467; converts agentcore-migration B4/B5/B6 from docs to issues.
**Sequence:** 1 and 4 first (posture + decision), 2+3 next, 5 continuous, 6 rides #460, 7 after #461's threat model.

### Epic 3 — Accountable Runtime (verify, replay, budget every run)

**Pitch.** The harness moat, built almost entirely from parts that exist. The evals judge runs only offline; run-trace.v2 already captures replay-grade request snapshots with nothing to replay them; the orchestration spec itself says budgets "should land before any fan-out pattern ever does," yet no budget control has an issue number and #422 is blocked on it. This epic recombines `packages/evals` + run-trace.v2 + the #423 runs tree into the product story no competitor offers: answers checked against evidence before they render, any run replayable, every run bounded and costed. It is also the counter-position to every vendor selling unsupervised autonomy.

**Child issues:**

1. **Pre-ship verification pass: claims checked against tool evidence before the answer renders**
   Add an optional cheap-lane (Haiku) verifier that, before a tool-using answer finalizes, checks claims against the run's tool evidence and citation integrity, flagging or blocking unsupported statements. Generalizes #422's optional Verify worker from the build pipeline to chat runtime; depends on #434 (evidence persistence) and aligns with #433 (truthful citations). Ship behind a per-skill/per-lane flag with latency budget measured via the #384 benchmark harness pattern.

2. **Per-run budget enforcement: USD, token, and wall-clock caps that halt or degrade a run**
   Replace the lone hard-coded `maxToolIterations = 8` with an enforceable budget envelope evaluated in the agent loop, with a truthful "budget reached" surface in the receipt. Admin-set defaults per lane; the named prerequisite for ever building #422 fan-out. Uses #396 cost columns for accounting.

3. **Per-team quotas and admin cost dashboard**
   Group-level budgets and a usage-by-user/team view, built on #396 (cache-split columns), #423 (runs-tree rollup), #302 (admin page chassis), and Epic 1's group substrate. This is the Notion/Anthropic admin-comfort pattern the market scan flags as cheap and directly serving the IT win condition. Includes cost alarms per ENTERPRISE_READINESS's own unfiled list.

4. **Deterministic replay executor for any run**
   Promote STRETCH_GOALS row 7 ("Audit-Grade Replay") to tracked work: a recorded-response player over run-trace.v2 snapshots plus a pinned-model re-execution mode, a written determinism contract (temperature, tool nondeterminism), and retention alignment with #381 so the 30-day payload window doesn't silently truncate replayability. UI is a "why?" button on any receipt.

5. **Evidence graph: receipt → trace slice → cost share cross-linking**
   The linking layer the harness audit found missing: a receipt row expands to its replayable trace slice and its cost share. Depends on #359 P2/P3 (already open — not re-proposed) and #423; this issue is only the cross-links and navigation.

6. **Spike: AgentCore code-interpreter for computation over connector data**
   Deliberate, flagged revisit of #436's "no sandbox analog" anti-goal — Rob's call to reverse it. Timebox a spike: real aggregation over Salesforce/CSV rows and deterministic charts via the AgentCore code-interpreter primitive already in the substrate, gated behind #439 egress policy and issue 2's budgets. Output is a go/no-go memo, not shipped capability.

**Absorbs/depends:** depends on #423 (the spine), #434, #396, Epic 1 groups (for issue 3); references #422, #433, #359, #381, #439; promotes STRETCH_GOALS row 7.
**Sequence:** #423 first (already tracked) → 2 → 1 → 3 → 4 → 5; 6 anytime after #439.

### Epic 4 — Daily Habit Loop (reach, rhythm, first-run activation)

**Pitch.** The retention hook is currently inverted: schedules run, results land in an in-app digest that only renders after the user shows up, there is no email/Slack/push channel in the codebase (`lib/notifications.ts` has zero delivery code), and no PWA manifest means no home-screen presence and no mobile re-engagement at all. ROADMAP still points email delivery at #291, which is closed and was invite-email verification — a dangling reference, so this work is effectively untracked. A proactive agent that cannot reach your phone loses to Slack-native bots regardless of harness quality. This epic builds the reach channel, the morning ritual, and the connect-your-tools activation moment that makes week-one users into week-ten users.

**Child issues:**

1. **Push-delivered morning digest: email and Slack DM channels for scheduled-run results**
   Invert the pull digest: scheduled/webhook skill results and notification rollups delivered on a user-set morning schedule via SES email and a Slack incoming-DM channel. Re-files the dangling #291 reference in ROADMAP (that issue closed as invite-email verification) with correct scope. Respects notification preferences and links every item back to its thread and receipt.

2. **PWA: manifest, service worker, web push**
   `apps/web/public/` has no manifest or service worker. Add installable-PWA basics plus web-push for schedule results and share events — the only mobile re-engagement channel that doesn't require an app store. Untracked anywhere today; compounds issue 1.

3. **Post-onboarding tool discovery**
   Keep the WelcomeWizard focused on naming plus the live-capability tour. After a user has reached chat, use contextual, dismissible guidance to surface GitHub, Gmail, and Calendar only when a request would benefit from them. Connection remains an explicit Settings action with clear scopes; it must not block first-run completion.

4. **Projects/workspaces: a container above the flat thread list**
   Promote DESKTOP_PARITY_BACKLOG P1.2 (sized L, named the "weekly shadow trigger," its own sequencing says it's next) to a tracked issue: a `projects` container grouping threads, pinned skills, and files, designed against #413's team memory scope so the two land as one model, not two.

5. **Cmd-K global capability palette**
   Implement `docs/SLASH_CAPABILITY_PICKER.md`'s unified picker (skills, tool shortcuts like `/github`, app commands) plus a Cmd-K global palette (parity P2.2) — today only Cmd-, exists. Speed ceiling work that makes the daily driver feel faster than the shadow tools.

**Absorbs/depends:** re-files ROADMAP's #291 dangling reference; promotes DESKTOP_PARITY_BACKLOG P1.2 and SLASH_CAPABILITY_PICKER.md; coordinates with #413. The daily-feel bug set (#447, #466, #432, #434, #482) is already tracked — this epic assumes it lands and adds nothing there.
**Sequence:** 1 → 2 → 3 (fast follows) → 5 → 4 (largest).

### Epic 5 — Org Capability Flywheel (catalog, recommendation, eval-gated publishing)

**Pitch.** Four independent vendor convergences in H1 2026 (Dojo, Notion Custom Agents, OpenAI Workspace Agents, Claude Skills) plus Glass's Sensei confirm the market scan's verdict: shared, recommended, quality-gated skills are the differentiator of 2026. Comparative has the rails (#412 versioning/vetting/namespacing shipped day-one) and a seed (#78 shared work cards) but no browse surface, no usage-ranked gallery, no role-based recommendation, and no behavioral quality gate — vetting today is malice/lint, not "does it still pass its golden cases." This epic turns individually-built capability into org capital, which is the compounding moat a vendor product can't replicate in-house.

**Child issues:**

1. **Org skill catalog: browse, search, usage-ranked gallery**
   A catalog surface beyond the two-group Skills page ("Your skills"/"Shared with you"): browse what the org uses, ranked by real usage, with #412's namespacing and version metadata displayed. #78's opt-in work cards become the social-proof feed inside it.

2. **Role + org-graph skill recommendation**
   Rank "recommended for your role" by role plus social/org graph (teammates' adoption), the Sensei/Glass pattern already sketched in project notes. Surfaces in the existing recommendation cards and the onboarding activation step (Epic 4.3). Depends on Epic 1's group substrate for role/team signals.

3. **Eval-gated skill publishing: a scorecard on every published version**
   Apply the #301 model-gauntlet pattern to skills: candidate versions run against golden cases via the existing `pnpm eval` harness; regressions block publish/promote at the #412 versioning and #411 publish-tier seams; the scorecard persists next to the version. Converts "trust the author" into "read the scorecard."

4. **Promote-to-starter path and role-based starter packs**
   A one-click admin path from catalog hit to starter-skill status, plus role-based packs (the 8 seedable starters become per-role bundles). Directly answers ROADMAP open item #6 (catalog cold start), undecided since week 5.

5. **Org-wide visibility tier for shares**
   J5's named-recipient `shares` model gains an org-visible tier so a skill/app can be published to everyone without enumerating recipients, honoring #411's tri-mode data badges and Epic 1's groups. The distribution mechanism the skills-catalog flywheel in ROADMAP assumes but the schema can't express.

**Absorbs/depends:** builds on #412, #78, #411, #301-pattern, Epic 1 groups; answers ROADMAP open item #6.
**Sequence:** 1 → 4 → 3 → 5 → 2 (reco last; needs usage data from 1).

## C. Deliberately NOT doing

1. **Tier-2 agent teams / multi-agent workrooms.** #421's Tier-1 single-writer doctrine stands; the spec documents the 4× cost math, and the market scan rates sub-agent orchestration hype-tier for 50–500 orgs. Revisit only after Epic 3's verification pass ships — a critic loop is that capability productized, and it should be built on it, not before it.
2. **Computer-using agents.** Brittle, RPA-shaped, and directly contrary to the receipts-and-evidence trust story. Copilot can have this one.
3. **Real-time voice.** Hype tier at this org size; no journey requires it.
4. **Cross-provider (non-Bedrock) routing and latency-based load balancing.** Explicitly out of scope in #303, and "everything inside your AWS account" is the residency counter-position — diluting it for marginal routing gains is strategically backwards.
5. **New connector proposals beyond the ROADMAP tier tables.** M365/Workfront/Databricks/Salesforce/ServiceNow/SAP sequencing is fully specified in ROADMAP.md; the gap is build priority, not roadmap work. The one adjacent build here is Epic 4.1's Slack *delivery* channel — full Slack-native presence (stretch #8) waits until digest delivery proves the channel earns it.
6. **SOC2 certification pursuit.** Single-org internal on the org's own AWS; a shared-responsibility matrix (Bedrock/AgentCore vs shell) inside #461's readiness packet answers the real question at near-zero cost.
7. **ADLC-style governance ceremony.** Glean's 7-stage lifecycle is process weight built for 5,000-seat rollouts; Comparative's answer is enforced-by-construction controls (#410/#436/#439 + Epic 3), not stage gates.
8. **Re-speccing multi-model routing.** #295/#301/#302/#303/#305 are fully specced; the only open question is build order, which belongs in sprint planning, not this addendum.

## D. Top 5 highest-conviction bets, ranked

1. **Pre-ship verification pass (Epic 3.1).** Cheapest build on the list — judge, evidence, and receipts all exist — with the largest trust payoff, and it converts the product's honesty spine into a demonstrable, falsifiable claim no competing harness makes. Prior market research already called verification loops the moat; this is the moat, filed.
2. **SSO + SCIM + group substrate (Epic 1.1–1.3).** The single dependency under org-wide rollout, four accepted specs, team budgets, and org sharing. Every week it stays untracked, every other epic's ship date is fiction.
3. **Push-delivered digest + PWA (Epic 4.1–4.2).** Inverts the retention hook from pull to push for a few hundred lines of delivery code. Highest retention-per-effort ratio in any report, and it makes J3's already-shipped proactivity visible instead of latent.
4. **Org skill catalog + role recommendation (Epic 5.1–5.2).** The market's most-validated 2026 differentiator (four vendor convergences plus Glass), sitting one browse surface away from rails that already shipped. This is what makes capability compound across the org instead of per-person.
5. **Private subnets + SIEM export (Epic 2.1–2.2).** The two instant questionnaire fails an IT reviewer hits before reading any code. Fixing them is unglamorous infra work that buys more review credibility per engineer-day than anything else open.
