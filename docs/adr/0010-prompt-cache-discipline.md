# ADR 0010: Prompt-cache discipline: stable prefix, volatile suffix, pinned constraint layer

- **Status:** Accepted
- **Date:** 2026-07-19
- **Deciders:** Rob (owner), Claude/Codex (implementation)

## Context
Comparative runs interactive chat on Bedrock with prompt caching, where the cache prefix only pays off if the tools+system bytes are identical turn over turn — but every turn also needs live material (the clock, per-turn context receipts, nonce-marked recommendation cards) and the assistant must never lose its governing constraints when history is later summarized. A single naive system string forces a false choice: fold in the clock and pay a cache-write premium on every turn, or bury governance/skill instructions inside a region a future summarizer could rewrite or drop. Bedrock evaluates cache checkpoints in `tools → system → messages` order (`packages/agent/src/clients.ts:277-283`), so the boundary between stable and volatile content is a real, load-bearing seam, and honesty (the product's spine) depends on constraints outliving compaction.

## Decision
Split system context into two fields with a hard checkpoint between them, and pin governing constraints into the stable half. The stable `systemPrompt` (identity line + preamble + capability summary + `PINNED_PRECEDENCE_NOTE` + active-skill block) is emitted followed immediately by `{ cachePoint: { type: "default" } }`, and the `volatileSystemSuffix` (recommendation cards, context receipt, current clock) is pushed *after* that checkpoint — `packages/agent/src/clients.ts:284-293`, threaded through `packages/agent/src/loop.ts:112-127` and assembled in `apps/web/lib/chat-context-pack.ts:464-518`. Governing content — precedence/governance note, the active skill's operating instructions, and approved memory — is rendered deterministically (no timestamps or nonces) into that stable prefix and re-injected verbatim from its authoritative source each turn, above any summarizable region (`apps/web/lib/pinned-context.ts:3-16,38-68`), while the summarizer input contract structurally excludes the pinned block (`apps/web/lib/summarizer-input.ts:3-20,39-68`).

## Consequences
- **Cache hit rate is protected:** the clock, receipts, and nonce-bearing recommendation cards vary every turn but sit below the checkpoint, so they never invalidate the cached tools+system prefix (`clients.ts:277-293`); a second checkpoint after the tool definitions keeps the larger tools cache warm across system-prompt changes (`clients.ts:435-437`).
- **Honesty is protected across compaction:** governance and the active skill live in the byte-stable prefix, above history, and are re-injected verbatim — a rolling summary cannot silently rewrite or drop them, and `buildSummarizerInput` cannot even receive the pinned block as a parameter (`summarizer-input.ts:39-49`).
- **The pin is observable and enforced:** `buildPinnedContextReceipt` hashes the full stable prefix (`pinned-context.ts:86-104`); ordinary turns, summary updates, and receipts must leave the hash byte-identical, and only a real source change (memory/instruction/governance edit or skill (de)activation) may rotate it. The hash itself renders only in the volatile suffix / Run Inspector, never inside the pinned block.
- **Cost:** any new standing content now carries a mandatory design decision — it must declare whether it belongs in `systemPrompt` (stable, cacheable, therefore deterministic — no per-request bytes) or `volatileSystemSuffix` (per-turn). Getting this wrong is silent: volatile bytes in the stable slot turn every turn into a cache miss that still pays the cache-write premium, and stable-but-nondeterministic content (a stray timestamp or nonce) does the same. Determinism is a hard requirement for anything pinned — `renderPinnedActiveSkill` must stay nonce-free and encodes reserved frame markers out of skill bodies rather than trusting them (`pinned-context.ts:29-31,43-68`).
- **Forecloses** treating the system prompt as one free-form string: the two-field contract (`ChatContextPack.prompt`, `clients.ts:110-115`) is now the only supported shape, and future context sources must route through it rather than concatenating into a single blob.

## Status notes
Checkpoint emission is capability-gated (#797 P1): both `cachePoint` blocks are emitted only when the model's registry entry sets `supportsPromptCaching` (`packages/agent/src/models.ts`), threaded through `ConverseStreamParams.supportsPromptCaching`. A model that cannot cache keeps the stable-prefix / volatile-suffix split — the seam is about determinism as much as cache hits — and simply pays no checkpoint.

The precedence ladder is (1) platform governance, (2) authorization/protected keys, (3) organization standing instructions, (4) the active skill's operating instructions, (5) the user's own layer (custom instructions + approved Vault memory), (6) the thread — nearer-to-the-work wins for guidance, protected keys never yield; a team layer is deferred to #438 P2 and will slot between org and skill (`packages/agent/src/instruction-layers.ts`, `PINNED_PRECEDENCE_NOTE`); those slots are inert until the #413 org/team scope substrate lands, at which point the pinned layer's ordering is extended (not revisited).

#771 (context lifecycle) ships the compaction this ADR anticipated, and both edits act strictly behind the checkpoints: stale tool-result clearing (`packages/agent/src/context-lifecycle.ts`) rewrites only `messages`, and the rolling summary is rendered at the head of `messages` as nonce-framed layer-6 data by `buildTurnContext`, never into `systemPrompt`. The summarizer boundary moved from `apps/web/lib/summarizer-input.ts` to `packages/agent/src/thread-summary.ts` (same contract — conversation messages only, the pinned block is not a parameter) so the evals can exercise the production prompt. `apps/web/__tests__/chat-context-pack.test.ts` pins the receipt hash byte-identical with and without a summary.
