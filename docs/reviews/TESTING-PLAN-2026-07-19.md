# Testing Improvement Plan — Comparative

## A. Verdict

Testing is **broad but hollow in the middle**: 119 unit files, 73 e2e tests across two well-designed harnesses, 78 eval cases with real injection coverage on Gmail/Salesforce/web-search, and a real-Postgres scoping suite — genuinely above-average for a repo this age. But the strength is concentrated in pure logic and mocked UI shells, while the load-bearing paths run uncovered. The three biggest holes: **(1) the chat streaming spine is untested at every layer** — `app/api/chat/route.ts` (833 lines) imported by no test, `lib/sse.ts` untested, every e2e SSE stream is a pre-baked fixture, and "Stop generating" has never been clicked; **(2) schema drift has no gate** — drizzle snapshots are deliberately frozen at 0023 while migrations run to 0035, so nothing verifies the TS schema matches the handwritten SQL until prod runtime; **(3) injection coverage has structural gaps that undercut its credibility** — web-fetch (the one nonce-framed built-in tool) has zero behavioral evals, memory poisoning (read and write paths) is untested, generic MCP results get no framing at all, and every injection case runs exactly once, so a 1-in-5 failure mode passes nightly. Secondary but real: `memory-capture.ts` (645 lines) and `run-actions.ts` (310 lines, ownership checks) have zero coverage, and the 12-minute CI critical path rests on un-sharded, dev-mode-compiled Playwright runs already patched once for deterministic timeouts.
